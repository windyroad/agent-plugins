# Hooks and Gates

Learnings about PreToolUse/PostToolUse gate behaviour, markers, and expiry.

## What You Need to Know

- **`/tmp` marker accumulation is real and large, and it caps how far the candidate-SID window can widen.** Measured on the dev machine 2026-08-20: **1,435** `*-announced-<UUID>` markers, **1,002** `manage-problem-grep-<UUID>-*` create-gate markers, **266** `claude-risk-<UUID>/` dirs. Nothing reaps them. This matters beyond untidiness because `wr-itil-mark-create-gate` writes its marker under **every** candidate SID (ADR-050 Option C, P260) — the 1,002 create-gate markers are what a 1440-minute enumeration window already produces. So the obvious fix for a shim that finds no candidate on a >24h session (`SESSION_CANDIDATE_WINDOW_MINS=10080`) scales the per-write fan-out across the same growing corpus, which is the accumulation pathology P124 was raised about. Before touching the window, check whether a reaper is the actual prerequisite. Tracked as P502. <!-- signal-score: -4 | last-classified: 2026-08-30 | first-written: 2026-08-20 -->
- **Read-only style-guide and voice-tone reviewers return the verdict; the PostToolUse hook must parse it and fail closed.** P469 traced the live path end to end: the old hooks ignored `tool_response`, read process-global `/tmp/*-verdict` files, and treated absence as PASS, so a FAIL could still create the gate markers. The fixed hooks accept only the first canonical PASS heading from the completed `Agent` output; VIOLATIONS FOUND, GUIDE UPDATE NEEDED, malformed, or missing output writes nothing. Never forge a reviewer verdict file. Installed caches retain the old behaviour until the patched packages are released and refreshed. **Separate P466 risk-scoring caveat:** `wr-risk-scorer:pipeline` has no Bash, so give it the staged change inventory and do not assume it can inspect the index. <!-- signal-score: 5 | last-classified: 2026-08-30 | first-written: 2026-07-26 -->

- **The risk-scorer's `RISK_CWD:` binding contract exists only in the Codex build of the agent, so the `SubagentStop` receipt path is dead on Claude Code.** `scripts/codex-agents.mjs` appends a `## Codex assessed-checkout binding` section when it generates `.codex/agents/wr-risk-scorer-pipeline.toml`; `packages/risk-scorer/agents/pipeline.md` never carries it, and its Below-Appetite Output Rule whitelists only the report, `RISK_SCORES:` and `RISK_BYPASS:`. The completion bridge requires exactly one `RISK_CWD:` line in the agent's output, so every Claude Code risk-scorer `SubagentStop` rejects with `missing-risk-cwd` — harmless while `PostToolUse:Agent` fires, but it means the receipt cannot rescue a dispatch where that hook does not fire, and it overwrites the single shared diagnostic at `$TMPDIR/claude-risk-pending/subagent-stop-diagnostic.json` that the Codex path relies on for its own failures. Read the diagnostic before assuming an event never fired. P477 / P402. (2026-08-21.) <!-- signal-score: -2 | last-classified: 2026-08-30 | first-written: 2026-08-21 -->
