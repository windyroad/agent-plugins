# Hooks and Gates

Learnings about PreToolUse/PostToolUse gate behaviour, markers, and expiry.

## What You Need to Know

- **A FRESH architect spawn returning PASS still writes no marker if its verdict line is a markdown heading (`## Architecture Review: PASS`) rather than bold — and the deny message's own recovery names the wrong SID source.** Distinct from the SendMessage-resume miss above: the spawn was synchronous and fresh, the PASS unambiguous, and the gated Write was still denied. The deny text says to derive the SID from the newest `architect-plan-reviewed-*` / `architect-announced-*` basename; the gate actually reads the `session_id` on the Write's stdin, which can be a different UUID recorded in `/tmp/itil-runtime-sid-<user>-<n>.current`. Asserting under the announce-marker UUID alone re-blocks. Recovery that works: read every `/tmp/itil-runtime-sid-*.current` value and `touch /tmp/architect-reviewed-<sid>` + `rm -f` its `.hash` sibling for each recent candidate — same candidate-set discipline the create-gate marker uses per ADR-050 Option C. Tracked as P468; the ISSUES-FOUND-substring precedent is P181. (2026-07-26, P438 iter.) <!-- signal-score: 2 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
- **`/tmp` marker accumulation is real and large, and it caps how far the candidate-SID window can widen.** Measured on the dev machine 2026-08-20: **1,435** `*-announced-<UUID>` markers, **1,002** `manage-problem-grep-<UUID>-*` create-gate markers, **266** `claude-risk-<UUID>/` dirs. Nothing reaps them. This matters beyond untidiness because `wr-itil-mark-create-gate` writes its marker under **every** candidate SID (ADR-050 Option C, P260) — the 1,002 create-gate markers are what a 1440-minute enumeration window already produces. So the obvious fix for a shim that finds no candidate on a >24h session (`SESSION_CANDIDATE_WINDOW_MINS=10080`) scales the per-write fan-out across the same growing corpus, which is the accumulation pathology P124 was raised about. Before touching the window, check whether a reaper is the actual prerequisite. Tracked as P502. <!-- signal-score: 2 | last-classified: 2026-08-20 | first-written: 2026-08-20 -->
- **The style-guide and voice-tone reviewers are spawned read-only, so they cannot write the verdict file their own contract names — and they will ask you to write it for them.** Both closed their reviews in the P438 iter reporting they had no Bash and could not `printf` to `/tmp/style-guide-verdict` / `/tmp/voice-tone-verdict`. Do not forge the verdict on their behalf: a caller-written verdict is not an independent review, and if the file turns out to be load-bearing that is the hollow-marker class (P348). Treat the returned verdict text as the authority and let the PostToolUse mark hook do its job. Tracked as P469 — which mechanism is actually live for each gate is its first investigation task. (2026-07-26.) **Wider than P469's title says: `wr-risk-scorer:pipeline` has no Bash either**, so it cannot run `git diff --cached` and scores a commit by reading the working tree instead of the staged index — it flagged that gap itself, as its own Risk 4, and could not distinguish staged from unstaged. Give it the change inventory in the prompt; do not assume it can see what you staged. (P466 iter 2026-08-21.) <!-- signal-score: 3 | last-classified: 2026-08-21 | first-written: 2026-07-26 -->
