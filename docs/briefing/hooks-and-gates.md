# Hooks and Gates

Learnings about PreToolUse/PostToolUse gate behaviour, markers, and expiry.

## What You Need to Know

- **A Bash-routed write to a governed path fires no edit gate and no post-write bookkeeping — and tells you nothing.** The five edit gates bind the `Edit|Write` tool matcher. A shared classifier now re-shapes *some* Bash writes into Write-shaped events, but only literal redirection, heredocs and `tee` operands in simple commands. A `cp`, a `python3 - <<PY`, a `perl -pi`, a `sed -i`, or anything inside a `for` loop or behind a glob is unclassified — it passes silently, by decision, and the architect hash refresh and compendium regeneration do not fire either. In a bypass-permissions session the harness steers you onto exactly that path, so this is the DEFAULT route, and governance edits routinely land ungated with no denial to signal it. After any Bash-routed write under `docs/decisions/`, run `wr-architect-generate-decisions-compendium` yourself and check `grep -ac "### ADR-" docs/decisions/README.md` against HEAD — otherwise the next ordinary Edit is denied for drift you cannot attribute to anything you did. The boundary and its rationale are recorded in ADR-131; P503 stays open for the residual. (2026-09-19.) <!-- signal-score: 1 | last-classified: 2026-09-19 | first-written: 2026-09-19 -->

- **Candidate-SID enumeration remains an ITIL create-gate tradeoff, not an oversight-authority pattern.** ADR-050, Capture the runtime stdin `session_id`, deliberately bounds `wr-itil-mark-create-gate` fanout to 1440 minutes and accepts a recoverable fail-closed denial when a long-running caller is absent. Do not widen the window or pick a newer unrelated session. Architect and JTBD oversight instead use the exact successful standalone command's `PostToolUse:Bash` session evidence, as recorded in [Hook Authoring - Shell Portability](./hook-authoring-portability.md). P502, The marker shim's 24h candidate-SID window excludes long sessions, closed after current-source and published-package verification confirmed that redesign. <!-- signal-score: -1 | last-classified: 2026-09-19 | first-written: 2026-08-31 -->
- **Read-only style-guide and voice-tone reviewers return the verdict; the PostToolUse hook must parse it and fail closed.** P469 traced the live path end to end: the old hooks ignored `tool_response`, read process-global `/tmp/*-verdict` files, and treated absence as PASS, so a FAIL could still create the gate markers. The fixed hooks accept only the first canonical PASS heading from the completed `Agent` output; VIOLATIONS FOUND, GUIDE UPDATE NEEDED, malformed, or missing output writes nothing. Never forge a reviewer verdict file. Installed caches retain the old behaviour until the patched packages are released and refreshed. **Separate P466 risk-scoring caveat:** `wr-risk-scorer:pipeline` has no Bash, so give it the staged change inventory and do not assume it can inspect the index. <!-- signal-score: 8 | last-classified: 2026-09-19 | first-written: 2026-07-26 -->
