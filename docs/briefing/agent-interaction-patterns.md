# Agent Interaction Patterns

Cross-session learnings about the assistant's own interaction habits — framing-validation, re-stage traps, user-frustration signals, and the small rules that reduce wasted rounds.

> **Sibling brief**: gate-marker propagation, P119 / P122 / P124 helper bugs (P142 fix), and architect-agent gate visibility within AFK iteration subprocesses live in `agent-hook-gate-quirks.md` (split out 2026-05-03 per P145 MUST_SPLIT). Read alongside this file when debugging hook-deny chains.

- **A claim from a hook, a detector, a subagent, or a queue is NOT pre-verified — it is an assertion with a timestamp older than the artefact it describes.** Four instances on 2026-08-20, each one `Read` from falsification: a SessionStart queue entry claiming an ADR still said X (reconciled three weeks earlier, and the maintainer was asked to re-decide a settled question); `check-autocreate-rfc-scope.sh` reporting `under_scoped=7` relayed as a criterion "firing for real" (already ruled on 2026-07-03, and the detector cannot know that so it re-emits every retro); a reviewer's file count carried into an ADR 31 lines from the agent's own contradicting count; a hang-off pre-filter supplying an `open/` path for a `closed/` ticket. **Open the artefact before repeating what something else said about it.** (P434, third scope extension.) <!-- signal-score: 7 | last-classified: 2026-08-30 | first-written: 2026-08-21 -->
- **`test -d packages && grep -rl ... packages/` is a vacuous pass, not a guard.** The `&&` short-circuits: a missing root produces no output, which reads as "returns nothing" and passes — the exact failure the guard was added to prevent. Assert the root's existence as its OWN step, then plant a known-positive and assert it is FOUND, then assert the corpus is clean. A search that cannot find a planted match is broken regardless of what it reports. - **A reviewer subagent can assert a gate blocker that a ratified ADR already retired — check the named function before queueing it.** The JTBD reviewer's closing note on P432 (2026-09-19) said that adding a release row and a card to a ratified story map "changes the map's content, so the hash will no longer match and the map's ratification will need re-confirming". ADR-103 retired exactly that deadlock, and `oversight_map_substance_keys()` in `packages/itil/lib/story-oversight.sh` returns `storyMapId title persona secondaryPersona traces backbone caption historicalPreRfcRows` — rows and cards are outside the basis by construction. The architect, reviewing the same change, read the function and said so. Verified after rendering: the hash was byte-identical. Taking the reviewer's note at face value would have queued a ratification blocker that does not exist and stalled the vehicle. Reviewers reason from prose they have read; the hash basis is a function, so read the function. Same class as the memory note on probing tooling before declaring it unavailable.

### Re-verify a ticket's recorded blocker against the tree before you accept it (2026-09-19)

A blocker written into a ticket body is a snapshot of the tree on the day someone wrote it, and nothing re-checks it. P290 carried a bold BLOCKER note holding its whole Phase 2 on "RFC-012 S2 CI wiring is unbuilt", plus an ADR-074 hold on two decisions recorded as `human-oversight: unconfirmed`. Both had been discharged months earlier — the CI job had landed and run green, and both ADRs were `confirmed`. Two greps, about a minute, turned a ticket that reads as fully blocked into one with landable work.

The two cheap checks worth making reflexive on any ticket whose body claims a hold: grep the named workflow / script / directory for the thing said to be missing, and read the frontmatter marker of every decision the hold cites rather than trusting the ticket's report of it. Then write what you found back into the ticket in the same commit — the next reader gets the correction instead of re-deriving it. Ticket bodies also keep superseded directives alive further down the file after the headline note is updated, so sweep for the old instruction too, not just the paragraph you came for.
