## What You Need to Know

- **A PreToolUse gate (external-comms / commit-msg) denies the WHOLE Bash call, so a combined `git add … ; git commit …` loses the `git add` when the commit blocks.** The gate intercepts before execution — the entire tool call never runs, including the staging that preceded the commit in the same Bash invocation. So when the commit-msg external-comms gate blocks, your stage is gone; after satisfying the gate (delegate to `wr-risk-scorer:external-comms` with the verbatim body), re-`git add` THEN commit (or `git commit --amend` to fold the rest into the same commit and preserve the ADR-014 one-commit grain — `--amend --no-edit` reuses the already-PASSed message hash so the gate marker stays valid, no re-review).
