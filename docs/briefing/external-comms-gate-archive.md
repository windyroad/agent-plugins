## What You Need to Know

- **A PreToolUse gate (external-comms / commit-msg) denies the WHOLE Bash call, so a combined `git add … ; git commit …` loses the `git add` when the commit blocks.** The gate intercepts before execution — the entire tool call never runs, including the staging that preceded the commit in the same Bash invocation. So when the commit-msg external-comms gate blocks, your stage is gone; after satisfying the gate (delegate to `wr-risk-scorer:external-comms` with the verbatim body), re-`git add` THEN commit (or `git commit --amend` to fold the rest into the same commit and preserve the ADR-014 one-commit grain — `--amend --no-edit` reuses the already-PASSed message hash so the gate marker stays valid, no re-review). Witnessed 2026-06-28, review-problems iter: only the pre-staged `git mv` renames committed; README + 22 Origin stamps were silently dropped from the first commit. - **The external-comms gate also over-fires on read-only `gh api …/security-advisories` polls** — review-problems Step 4.5 inbound-discovery treats an INBOUND read as an OUTBOUND draft and blocks it. ## Rotated 2026-08-30 (P512 retro, Branch B split-by-date)

- **When the session gives you no synchronous dispatch, hand-invoke the mark hook with the reviewer's genuine verdict — do not fabricate one, and do not `touch` the marker.** The sanctioned recovery is to run the writer the hook would have run, feeding it the verdict the reviewer actually returned. `risk-score-mark.sh` reads a PostToolUse-shaped payload on stdin; the four fields it needs are `tool_name: "Agent"`, `session_id`, `tool_input.subagent_type` (must contain `risk-scorer.pipeline` — note `.` is a regex wildcard there, so the `wr-risk-scorer:pipeline` colon form matches fine), and `tool_response.content[]` carrying a `{type:"text", text:"RISK_SCORES: commit=N push=N release=N"}` entry. Build it with `python3 -c 'import json; print(json.dumps({...}))' > /tmp/f.json` and pipe: `bash packages/risk-scorer/hooks/risk-score-mark.sh < /tmp/f.json`. It writes the full marker set (`commit`/`push`/`release` + `-born` siblings + `checkout-id` + `state-hash`) under `${TMPDIR}/claude-risk-<SID>/`, so the gate then passes on the real score. Two things this is NOT: it is not `touch`ing a marker (the hook derives checkout-id and state-hash, which a bare touch cannot), and it is not inventing a verdict (the text is the reviewer's own output, pasted). Any tree edit after the mark drifts `state-hash`, so re-score and re-mark.
