## What You Need to Know

> **Sibling brief**: promptfoo SKILL-eval authoring pitfalls (Tier-A regex, Nunjucks `{% raw %}`, negative-clause → Tier-B routing) live in [`promptfoo-eval-authoring.md`](./promptfoo-eval-authoring.md). Load when debugging `promptfooconfig.yaml` evals.

- **A supersede-in-part scope is a list of clauses, not a list of mechanisms — and an evidence arm the old ADR never recorded is NEW substance, not part of the scope.** Naming only the two grep predicates a decision retires under-states what it displaces: the old ADR's *chosen option* enumerated those predicates in its shape list, and its labelled fixture set (designated the regression suite under ADR-052) labels most of its cases by those predicates, so both go too. State each displaced clause individually, say what happens to the fixture labels, and say explicitly that the old ADR is **not** renamed to `.superseded.md` — partial supersession leaves it in force, and the compendium renders no back-link on a partially superseded entry, so its title keeps advertising the retired mechanisms. Separately: if the new decision *adds* an evidence arm the old ADR's closed literal-list never carried, do not widen the supersede scope to cover it — record it as the new decision's own substance composing with the old shape, with its own driver and bound. The architect raises `[Amendment To Ratified Decision]` on the widened form and `[Missing Supersession]` on the under-stated one; both are wording-level and both cost a full review round if you draft past them. (P463 → ADR-129, 2026-09-19.)

- **The story `done` gate has two non-equivalent statements; the manual path is the weaker one.** `manage-story` SKILL.md line 112 (the manual `manage-story <NNN> done` gate) reads criteria-ticked AND (linked RFC `closed` **OR** the RFC's other stories closed); line 134 and `manage-problem` line 236 (the auto-fire sweep at `manage-rfc` close) read criteria-ticked **AND** RFC `closed`, with line 236 supplying a trace-coupling rationale line 112 drops. So a story whose criteria are all ticked, whose siblings are terminal, and whose RFC is still `verifying` is done-eligible on the manual path and not on the auto-fire path — the normal shape when the last story under a multi-story RFC lands first. Use line 112 for a manual transition and say so. Related asymmetry: `archived` counts as "closed" for line 112's OR branch but NOT as "done" for `manage-problem` line 238's problem-level Known Error → Verification Pending trigger, so one archived sibling holds the *problem* even after every story is terminal. (P548, witnessed on STORY-044 / RFC-046, 2026-09-19.)

- **The architect reviewer will ask you to author an `docs/rfcs/RFC-NNN-*.md` body for a fix whose release row already exists — it is reasoning from the pre-ADR-103 corpus, and it withdraws when you cite ADR-103.** The corpus resolves this correctly: ADR-073 says the RFC is *stories in a user story map*, and ADR-103 says a release row **is** an RFC. But the reviewer reaches ADR-071/072/073 from the problem and does not reach ADR-103 from there unprompted, so it returns ISSUES FOUND with *"the RFC this fix implements does not exist"* even when `wr-itil-check-fix-rfc-trace` returns clean on the row. Do not author the document — that is the P508 defect, and the fix-trace predicate is the authority, not the reviewer's file check. Name ADR-103 (and ADR-104) in the review prompt from the start, or expect one wasted round. Cost when unprompted: a full extra architect spawn. (P437 iter 2026-09-19; recorded on P508.)
