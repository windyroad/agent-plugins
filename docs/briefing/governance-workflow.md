# Governance Workflow

Cross-session learnings about ADRs, architect/JTBD reviews, risk scoring, and voice-tone.

## What You Need to Know

- **A ratified ADR's body is immutable — you cannot fix a stale one, not even editorially, not even with a supersession banner (ADR-116, 2026-08-13).** Once a decision carries `human-oversight: confirmed`, the only lawful change is a NEW decision that supersedes or deprecates it; editing the body, adding an amendment section, adding an `amends:` claim, or clearing the marker to rewrite history are all barred. This bites hardest when a ratified ADR inlines an example that a later ADR replaced: the stale block keeps teaching the superseded shape and there is no in-place fix. **Do not follow the amendment sections already in the corpus** — ADR-102's `### Amendment to ADR-060` and ADR-060's own `> **Amendment 2026-07-02**` banners predate ADR-116 and are migration debt tracked by P483, not precedent. The live pattern is ADR-115: a new ADR with `Supersedes: [ADR-NNN (in part - <named scope>)]`, the old body untouched, the old filename unchanged. That needs human ratification, so **an AFK iter cannot close a stale-ADR finding** — route it to the ticket that owns the document and land any interim mitigation somewhere unratified (a guide, a README) that can say "this block is a historical record of a superseded encoding, not a shape to copy from". Cost when missed: a full architect round, plus a ticket whose own investigation task directed the barred edit. (P466 iter 2026-08-21; the architect refused both the recolour and the banner.)

### Where you put a table in a governance index changes what the reconciler reports — the detectors bucket by line ranges between `^## ` grep hits (2026-07-26)

`reconcile-rfcs.sh` / `reconcile-readme.sh` / `reconcile-stories.sh` locate their sections with `grep -n '^## <Name>' | head -1`, then scoop every `| <ID> |` cell between one heading's line and the next section's. Two consequences bit P417. **(1) Placement is load-bearing.** Adding 42 rows as a `### Unranked` subsection BETWEEN the rankings table and `## Verification Queue` correctly cleared 42 `MISSING wsjf-rankings` lines; the same rows at the file tail would have bucketed as Closed claims and manufactured 42 spurious `MISMATCH` lines. **(2) A heading inside a fenced ```markdown block still matches**, and `head -1` takes the first hit. `docs/rfcs/README.md` documents the RFC body shape in a fenced block containing `## Closed scope (required when Status reaches closed)`, which prefix-matches `^## Closed` fifty lines above the real section — so `CLOSED_START` lands in the template, the Closed bucket swallows the rankings and queue tables, and `VQ_END` collapses below `VQ_START`, silently disabling the Verification-Queue check entirely. When editing any of these indices: never start a new heading with the string of an existing section heading, and re-run the detector to see which bucket your rows landed in rather than assuming. P417 detector defects queued as fix vehicles.
