## What You Need to Know

- **Skill invocation names are `{plugin-name}:{skill-dir-name}`**. The `name` field in SKILL.md is display-only. Directory names must not contain colons. <!-- signal-score: -1 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->

## What Will Surprise You

- **The `skills` npm package installs to 45 AI tools** (Codex, Cursor, Cline, etc.), not just Claude Code. If cross-tool distribution is ever needed again, that is the mechanism. <!-- signal-score: -4 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **Repo-local skills live in `.claude/skills/<name>/SKILL.md` and are invoked as `/<name>` (no plugin prefix)** per ADR-030. They are NOT distributed via the marketplace. First example: `/install-updates` (end-of-session plugin refresh across this project + sibling projects). Constraints: first action must be `AskUserQuestion` listing cross-project side effects before any write, no hooks, no CHANGELOG. See ADR-030 for the full contract and when a new repo-local skill is appropriate vs. a marketplace skill. <!-- signal-score: -4 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **Windyroad npm package names drop the `wr-` prefix** that plugin names and marketplace cache keys use. Plugin name / marketplace cache key = `wr-itil`; npm package = `@windyroad/itil` (= source-directory name under `packages/`). `npm view @windyroad/wr-itil version` returns empty with exit 0 — silently — for ALL windyroad plugins if you guess the name wrong. Treat empty `npm view` output as "verify the package name" before concluding "the package is not public." (closed P092) <!-- signal-score: -1 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **A broken-manifest `/install-updates` run can gut `.claude/settings.json` — recover with `git checkout HEAD -- .claude/settings.json`.** Step 4 refreshes each plugin via `uninstall + install` (the P106 no-op workaround). `claude plugin uninstall` immediately strips the plugin's `enabledPlugins` entry; if every install retry AND the marketplace-refresh rollback then fail (e.g. a broken manifest already published — the 2026-05-18 P0), the plugin ends `lost` and is left absent from settings.json. The 2026-05-18 cascade cut settings from 13 enabled plugins to 2 (only the non-windyroad fallbacks survived), and any subsequent `claude -p` subprocess dispatch would have lost wr-* plugin access. **Recovery:** `.claude/settings.json` is git-tracked, so `git checkout HEAD -- .claude/settings.json` restores the pre-cascade enablement; then re-run `/install-updates` once the broken manifest is hotfixed. **Defense (P259):** the skill now snapshots settings.json before the uninstall+install loop and auto-restores the snapshot on any `lost` outcome — safe for same-run successes because `enabledPlugins` carries no version pin (the version advance lives in the global cache, not settings.json). The manual `git checkout` path remains the fallback when no snapshot was captured (settings.json untracked). (P259) <!-- signal-score: -4 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **`plugin.json`'s `hooks`/`skills`/`agents`/`commands` are RECOGNISED, type-checked component-path fields — a wrong-typed value on them is a HARD `claude plugin install` failure; a genuinely novel top-level key is only a warning.** The load-bearing split (per the [plugins reference](https://code.claude.com/docs/en/plugins-reference)): an **unrecognised** key → warning, plugin still loads; a **recognised** key with the **wrong type/shape** → load error. The 2026-05-18 P0 (all 11 plugins unparseable ~20 min) wrote per-surface maturity records at `hooks:`/`skills:`/`agents:` (recognised path-fields) → `Validation errors: hooks: Invalid input`. Fix (ADR-063 Amendment): nest under a NOVEL top-level `maturity:` key (unrecognised → warning-only). **Lessons:** extend `plugin.json` only via a new unrecognised key; gate pre-publish with `claude plugin validate --strict`; note `plugin.json` has two writers (ADR-063 maturity populate + ADR-021 version-sync) — both must keep it validator-clean. (P258 learning; P263 CI gate.) <!-- signal-score: -4 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
