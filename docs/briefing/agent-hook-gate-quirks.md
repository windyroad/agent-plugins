## What Will Surprise You

- **A new `docs/rfcs/RFC-*.proposed.md` file cannot be hand-authored, even holding architect PASS + jtbd PASS.** The write gates stack three deep and each is discovered only by attempting the Write and reading the BLOCK: architect marker, then jtbd marker, then the ADR-060 I1 create-gate, which demands `/wr-itil:capture-rfc` be invoked so the problem-trace invariant is enforced *before* the file lands. Holding both review PASSes is not a substitute — the third gate is about provenance, not approval. The cheap path is: run architect + jtbd first (they are the expensive ones, and an `ISSUES FOUND` writes no marker so each condition round costs a full fresh spawn per P400), then invoke `capture-rfc` with the problem trace, then Write your authored body over the skeleton. Note the marker shim needs a real SID — `CLAUDE_SESSION_ID` is empty in `claude -p` iters, so export it from the newest transcript basename under `~/.claude/projects/<project-slug>/` before calling `wr-itil-mark-rfc-capture-gate`, or it no-ops silently (P368). Same three-deep shape is likely on the story / story-map create-gates. Witnessed 2026-07-26, P431 iter. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-07-26 -->
- **Style-guide and voice-tone reviewers are intentionally read-only; their canonical output heading is the verdict.** P469 confirmed the old PostToolUse hooks did not consume that output: they read stale global `/tmp/*-verdict` files and treated an absent file as PASS. ### A reviewer agent can assert a staging state from a stale `git status` — check the index with `git show :<path>`, not the agent's read (2026-08-21)

The risk-scorer returned a remediation saying a commit body claimed two files were staged when "the working-tree status lists only" two others, and told the salvage session to stage them or amend the message. Both files were already staged: `git diff --cached --name-only` listed them, and `git show :<path> | grep '^human-oversight:'` returned the amended value **from the index**. The agent had read a status snapshot taken before the staging call.

Same class as the verify-at-the-observed-layer lesson: `git status` is a proxy, the index is the fact. When any reviewer makes a claim about what is or is not staged, confirm with `git show :<path>` before acting on it — the remediation here would have been a no-op edit or, worse, a commit-message amendment describing the commit inaccurately. Reviewers are right often enough that the reflex is to comply; this is the case where complying degrades the artefact. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-08-21 -->
