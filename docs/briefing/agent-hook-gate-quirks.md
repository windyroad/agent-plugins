## What Will Surprise You

- **A new `docs/rfcs/RFC-*.proposed.md` file cannot be hand-authored, even holding architect PASS + jtbd PASS.** The write gates stack three deep and each is discovered only by attempting the Write and reading the BLOCK: architect marker, then jtbd marker, then the ADR-060 I1 create-gate, which demands `/wr-itil:capture-rfc` be invoked so the problem-trace invariant is enforced *before* the file lands. Holding both review PASSes is not a substitute — the third gate is about provenance, not approval. The cheap path is: run architect + jtbd first (they are the expensive ones, and an `ISSUES FOUND` writes no marker so each condition round costs a full fresh spawn per P400), then invoke `capture-rfc` with the problem trace, then Write your authored body over the skeleton. Note the marker shim needs a real SID — `CLAUDE_SESSION_ID` is empty in `claude -p` iters, so export it from the newest transcript basename under `~/.claude/projects/<project-slug>/` before calling `wr-itil-mark-rfc-capture-gate`, or it no-ops silently (P368). Same three-deep shape is likely on the story / story-map create-gates. Witnessed 2026-07-26, P431 iter. <!-- signal-score: 0 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
- **Read-only reviewer agents (style-guide, voice-tone) report they cannot write their own `/tmp` verdict file — ignore the request to write it for them.** Both returned a closing paragraph asking the caller to `printf '<verdict>' > /tmp/<name>-verdict` because their tool grant is Read/Glob/Grep only. The marker the gate actually consumes is written by the PostToolUse hook on the `Agent` call, not by the agent itself, so the request is a false alarm — and hand-writing a verdict file is the hand-landed-marker anti-pattern.
