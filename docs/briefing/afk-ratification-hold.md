## What You Need to Know

- **THE WALL IS BROKEN, conditionally — read this before planning a hold (2026-07-26, commit `11d7a6d1`).** ADR-101 lands a bounded carve-out: an AFK loop MAY accept and implement a story that only decomposes already-confirmed substance. It is **opt-in and default OFF** — a project must set `afk_accept_pure_decomposition: true` in `.claude/itil.config.json`, which is gitignored and which no automated path may ever write, so check before assuming it applies. When it does apply, run `wr-itil-check-afk-accept-eligible <story-file>`: exit 0 means accept it (ratify LAST, after every substance write, then `git add` again) and implement; exit 1 means hold, and the reason is on stderr. Eligibility needs every traced ADR / JTBD / persona / map to be `confirmed`, plus a `## Decomposition basis` section with one entry per acceptance criterion citing only those confirmed parents. **Everything below still holds for any story that fails that predicate** — a story introducing a new decision, persona or job is still held, and P450's shape (blocking decision undiscoverable at selection time) is explicitly not covered. Note the bootstrap: ADR-101 is itself born `unconfirmed`, so until the maintainer confirms it, a story tracing it fails condition (a) and the carve-out cannot yet be exercised on its own implementation. <!-- signal-score: +9 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
- **The same commit closed the inverse hole (P465).** `itil-no-implement-draft-gate` now denies a commit whose `Refs: STORY-NNN` trailer names an `accepted`/`in-progress` story that is **not ratified** — unconditionally, for every adopter, no config. Before this, the ADR-096 claim that no unratified story could be implemented was held closed by decision alone and was open in code. Two consequences for an iter: accepting a story mechanically no longer works even mechanically, and a commit that stages a **substance** edit to the story it references is now denied, because the edit drifts the story's content hash — re-ratify, then re-commit. Ticking a criterion or advancing status is progress, not drift, and does not re-open. <!-- signal-score: +6 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
- **An AFK iter cannot land a code fix (unless the carve-out above applies). Plan it to author the fix vehicle and queue the ratification, and say so in the summary.** ADR-071 makes every fix go through an RFC; ADR-089 requires ≥1 story; ADR-095 requires story-map membership at capture; ADR-090 rule 3 + ADR-096 put human ratification at the story's `accepted` gate, and implementation requires `accepted`. Ratification has no AFK carve-out, so the iter walks map → RFC → story and stops at ratify — for ANY fix-implementation ticket, however small the fix. Four witnesses to date, the smallest being a 3-line env-var guard and a single `jq` branch; see [`afk-ratification-hold-witnesses.md`](./afk-ratification-hold-witnesses.md) for what each cost. <!-- signal-score: +7 | last-classified: 2026-07-26 | first-written: 2026-07-15 -->
- **The AFK shape.** Capture the story-map + story born `human-oversight: unconfirmed` (legal — unconfirmed artefacts may exist), do NOT edit the RFC's frontmatter `stories:` array (the derived `## Stories` body table via the reverse-trace helper is fine, and ADR-090 forbids an RFC referencing an unratified story anyway), queue ratify → accept → wire → implement to `outstanding_questions`, report partial-progress. Expect the JTBD gate to demand a new grounding job when the story's acceptance criteria map to no documented desired outcome — that is a fifth artefact, and writing it re-locks the JTBD gate via policy-file drift, so sequence jtbd-policy writes last. <!-- signal-score: 3 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
- **The bright line on what an AFK iter may author** (architect, P438 iter 2026-07-26): it may author any governance artefact born `unconfirmed`. It may NOT (a) write a `confirmed` marker, (b) transition an artefact into a state that authorises implementation, or (c) build implementation on unconfirmed substance. Authoring a born-unconfirmed job or map licenses nothing, which is why it is not the ADR-096 bypass class; accepting a story mechanically is, because that flips the commit-trailer gate open. <!-- signal-score: 3 | last-classified: 2026-07-26 | first-written: 2026-07-26 -->
