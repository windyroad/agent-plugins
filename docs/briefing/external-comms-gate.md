# External-Comms Gate

Learnings about the external-comms review gate (changeset / gh-issue / PR-body leak-review) — marker hashing, over-fire, background-agent non-persistence, and BYPASS behaviour. Split from hooks-and-gates.md 2026-07-03 for Tier-3 budget.

## What You Need to Know

- **The external-comms gate marker does NOT persist when the review runs as a *background* `Agent` (P402).** The review returns `EXTERNAL_COMMS_RISK_VERDICT: PASS` but the PostToolUse mark hook never fires for a backgrounded review agent, so the `.changeset/*.md` Write AND the subsequent `git commit` both re-block. **The `BYPASS_RISK_GATE=1` escape is GONE** (P377/RFC-029). The fix is a **synchronous** review: run `/wr-risk-scorer:assess-external-comms`, or pass **`run_in_background: false`** on a direct `Agent` dispatch. **The same non-persistence hits the `wr-risk-scorer:pipeline` commit-score marker** — a backgrounded scorer returns `RISK_SCORES:` and the gate still reports "No commit risk score found". The rule generalises to *every* marker-writing reviewer. `touch`ing the marker by hand is fragile — the gate's SID + key must match exactly, and an empty `CLAUDE_SESSION_ID` (P368 cold path) sends the write to a different dir than the gate reads. Prefer synchronous re-dispatch; where the session offers no synchronous path, use the hand-invoke recipe in the next entry rather than a bare `touch`. **RFC-041 codified the dispatch instruction at four SKILL surfaces + the `risk-gate.sh` DENY on 2026-07-03, and P402 closed on that basis — but P402 REOPENED 2026-08-20 (Known Error).** RFC-041 changed no mechanism; it wrote down a discipline. That works only where the caller both reads the instruction and *can* follow it, and neither holds universally: a caller that dispatches before hitting the DENY never sees it, and **some sessions expose no `run_in_background` parameter on the Agent tool at all** — every dispatch is asynchronous by construction, so "dispatch synchronously" is not an action available to them. Recurrence witnessed 2026-08-10 (addressr `b782a61f`, two full pipeline scores discarded on one commit) and reproduced twice in the 2026-08-20 audit session. **Also do not trust the ticket's stated mechanism**: its title says the hook "does not fire", and the 2026-08-20 evidence does not fit that — two 1-byte files in `.risk-reports/` sit past a guard an empty payload cannot satisfy, and `state-hash` in the risk dir is written by `risk-hash-refresh.sh`, not by the pipeline branch. Three mechanisms remain live (fires-with-empty-payload / fires-and-dies-before-the-marker-writes / never-runs) and P402 now carries tasks to tell them apart. <!-- signal-score: 13 | last-classified: 2026-09-19 | first-written: 2026-07-03 -->
- **Adding a surface to the external-comms gate is two edits, not one — the second is `lib/external-comms-key.sh`.** The key normalizer strips YAML frontmatter for exactly one surface, `changeset-author`. Any new surface whose content routinely carries frontmatter — Astro pages, MDX, Jekyll `_posts`, deck markdown — keys differently on each side: the gate hashes the whole `Write` payload including frontmatter, the reviewer hashes the prose body it was handed, and the PASS marker lands where the gate never looks. That is a permanent deny after a passing review, the P010 / P198 / #149 failure reproduced on a new surface. Extend the strip (or make the deny's wrapping instruction surface-specific) in the same change, and cover it with a gate-key/mark-key round-trip over a frontmatter-bearing fixture. Surfaced by the architect on the P435 design 2026-09-19, before the surface landed.
