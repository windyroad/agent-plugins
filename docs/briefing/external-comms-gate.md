# External-Comms Gate

Learnings about the external-comms review gate (changeset / gh-issue / PR-body leak-review) — marker hashing, over-fire, background-agent non-persistence, and BYPASS behaviour. Split from hooks-and-gates.md 2026-07-03 for Tier-3 budget.

## What You Need to Know

- **A PreToolUse gate (external-comms / commit-msg) denies the WHOLE Bash call, so a combined `git add … ; git commit …` loses the `git add` when the commit blocks.** The gate intercepts before execution — the entire tool call never runs, including the staging that preceded the commit in the same Bash invocation. So when the commit-msg external-comms gate blocks, your stage is gone; after satisfying the gate (delegate to `wr-risk-scorer:external-comms` with the verbatim body), re-`git add` THEN commit (or `git commit --amend` to fold the rest into the same commit and preserve the ADR-014 one-commit grain — `--amend --no-edit` reuses the already-PASSed message hash so the gate marker stays valid, no re-review). Witnessed 2026-06-28, review-problems iter: only the pre-staged `git mv` renames committed; README + 22 Origin stamps were silently dropped from the first commit. - **The external-comms gate marker does NOT persist when the review runs as a *background* `Agent` (P402).** The review returns `EXTERNAL_COMMS_RISK_VERDICT: PASS` but the PostToolUse mark hook never fires for a backgrounded review agent, so the `.changeset/*.md` Write AND the subsequent `git commit` both re-block. **The `BYPASS_RISK_GATE=1` escape is GONE** — the gate deny message now reads "There is no env override (P377/RFC-029 — BYPASS_RISK_GATE removed)". The only fix is a **synchronous** review: (a) run `/wr-risk-scorer:assess-external-comms`; OR (b) when you must use the `Agent` tool directly (an AFK iter subprocess that has the Agent surface), pass **`run_in_background: false`** so the mark hook fires in-turn — the gate's own deny message now names this. **The same non-persistence applies to the `wr-risk-scorer:pipeline` commit-score marker**, not just external-comms: a backgrounded pipeline scorer returns `RISK_SCORES:` but the commit gate still reports "No commit risk score found" — re-run it synchronously too. So the rule generalises to *every* marker-writing reviewer agent (external-comms leak-review AND pipeline commit-score). Manually landing the marker (compute the key via `packages/risk-scorer/hooks/lib/external-comms-key.sh::compute_external_comms_key`, `touch` it in `${TMPDIR}/claude-risk-$SID/`) is fragile — the gate's SID + key must match exactly, and an empty `CLAUDE_SESSION_ID` (P368 cold path) sends the mark hook's write to a different dir than the gate reads; synchronous re-dispatch is simpler and correct. ~10 recurrences in the 2026-07-03 RFC-037 session + the P179 iter 2026-07-03 (both external-comms AND pipeline markers, ~5 blocked commit attempts before synchronous re-dispatch). <!-- signal-score: 5 | last-classified: 2026-07-03 | first-written: 2026-07-03 -->
- **The external-comms gate also over-fires on read-only `gh api …/security-advisories` polls** — review-problems Step 4.5 inbound-discovery treats an INBOUND read as an OUTBOUND draft and blocks it. Fail-soft per the Step 4.5 contract (advisory note + skip the channel + continue); the read-only `gh issue list` / discussions polls do NOT trip it, so poll those separately. Don't try to satisfy an outbound-draft gate for a read-only poll. (2026-06-28, review-problems iter.) <!-- signal-score: 2 | last-classified: 2026-06-28 | first-written: 2026-06-28 -->
