# External-Comms Gate

Learnings about the external-comms review gate (changeset / gh-issue / PR-body leak-review) — marker hashing, over-fire, background-agent non-persistence, and BYPASS behaviour. Split from hooks-and-gates.md 2026-07-03 for Tier-3 budget.

## What You Need to Know

- **The external-comms gate marker does NOT persist when the review runs as a *background* `Agent` (P402).** The review returns `EXTERNAL_COMMS_RISK_VERDICT: PASS` but the PostToolUse mark hook never fires for a backgrounded review agent, so the `.changeset/*.md` Write AND the subsequent `git commit` both re-block. **The `BYPASS_RISK_GATE=1` escape is GONE** — the gate deny message now reads "There is no env override (P377/RFC-029 — BYPASS_RISK_GATE removed)". The only fix is a **synchronous** review: (a) run `/wr-risk-scorer:assess-external-comms`; OR (b) when you must use the `Agent` tool directly (an AFK iter subprocess that has the Agent surface), pass **`run_in_background: false`** so the mark hook fires in-turn — the gate's own deny message now names this. **The same non-persistence applies to the `wr-risk-scorer:pipeline` commit-score marker**, not just external-comms: a backgrounded pipeline scorer returns `RISK_SCORES:` but the commit gate still reports "No commit risk score found" — re-run it synchronously too. So the rule generalises to *every* marker-writing reviewer agent (external-comms leak-review AND pipeline commit-score). Manually landing the marker (compute the key via `packages/risk-scorer/hooks/lib/external-comms-key.sh::compute_external_comms_key`, `touch` it in `${TMPDIR}/claude-risk-$SID/`) is fragile — the gate's SID + key must match exactly, and an empty `CLAUDE_SESSION_ID` (P368 cold path) sends the mark hook's write to a different dir than the gate reads; synchronous re-dispatch is simpler and correct. ~10 recurrences in the 2026-07-03 RFC-037 session + the P179 iter 2026-07-03 (both external-comms AND pipeline markers, ~5 blocked commit attempts before synchronous re-dispatch); re-confirmed P400 iter 2026-07-03 (all four reviewer dispatches run_in_background:false, markers persisted first try); re-confirmed P398 iter 2026-07-03 (all reviewer + pipeline-scorer dispatches run_in_background:false, every marker persisted first try). **NOW FIX-RELEASED — P402 + P407 via RFC-041, 2026-07-03:** the fix direction is codified at the surfaces that instruct dispatch, so the discipline no longer relies on memory — the pipeline-gate DENY (`No <ACTION> risk score found`, `risk-gate.sh`) now instructs synchronous scorer dispatch, and the reviewer-wrapper/assess skills (`risk-scorer` pipeline + external-comms + assess-external-comms, `voice-tone` assess-external-comms) set `run_in_background: false` in their dispatch blocks (the external-comms-gate.sh DENY already carried it).
