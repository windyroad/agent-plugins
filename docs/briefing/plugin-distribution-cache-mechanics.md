# Plugin Distribution — Cache and Install Mechanics

Sibling of `plugin-distribution.md` — install/uninstall/refresh/cache/worktree/TUI quirks.

## What You Need to Know

- **Plugin hooks run from the marketplace cache, not from source.** After fixing hook code: push, `claude plugin marketplace update windyroad`, reinstall (`--scope project`), restart. Install at project scope to avoid breaking other active projects (ADR-004). <!-- signal-score: -6 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **Plugin renames need 4 coordinated steps**: rename + push + release; `claude plugin marketplace update windyroad`; edit `.claude/settings.json` directly to swap the enabled key (`claude plugin uninstall` refuses project-scope); restart. Then `npm deprecate "<old-pkg>@>=0.0.0" "<msg>"` (bare `*` returns 404). <!-- signal-score: -6 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->

- **TWO on-disk trees serve one plugin, and they can be at different versions.** `~/.claude/plugins/marketplaces/<name>/` is a git clone and serves **hooks**; `~/.claude/plugins/cache/<marketplace>/<key>/<version>/` serves **skills** and the `bin/` `$PATH` shims. Glob the wrong one and you conclude a plugin isn't installed. After a mid-session refresh the old version's `bin/` disappears and its shims leave `$PATH` — `wr-itil-mark-create-gate: command not found` until restart; invoke by absolute path from the new version dir to continue (P343-adjacent). (2026-08-20) **Because the marketplaces tree is a real git clone, its HEAD commit date is a network-free staleness probe** — `git -C ~/.claude/plugins/marketplaces/<name> log -1 --format=%ct HEAD` returns instantly and discriminates hard (measured 2026-08-21: four clones at 164, 124, 85 and 0 days). Reach for it before `npm view` when diagnosing "is this install current"; it needs no network and it is the axis that actually drifted in P506. (2026-08-21) <!-- signal-score: 1 | last-classified: 2026-08-30 | first-written: 2026-08-20 -->

## What Will Surprise You

- **BOTH trees can be arbitrarily far behind npm, and nothing on the machine ever checks.** `staleness-check.sh` compares this session's version against the highest version **on disk** — both operands local, no registry axis — so it prints a reassuring `on 0.59.0, 0.59.2 installed` while the true gap is forty releases, and no restart can change either operand. Observed 2026-08-20: the clone pinned 989 commits back at `wr-itil` 0.59.2, the cache at 0.59.0, npm at **1.1.1**; `../addressr` consequently emitted a story map in the pre-renderer format retired three months earlier, and it looked deliberate rather than broken. `claude plugin marketplace update <name>` repairs the clone and pulls the cache forward. **Verify against `npm view <pkg> version`, never against the nudge.** (P506) <!-- signal-score: 0 | last-classified: 2026-08-30 | first-written: 2026-08-20 -->
- **Codex plugin installation can expose new skills before the current shell inherits the plugin's `bin/` shims.** After installing `wr-retrospective@0.28.0`, the skill loaded in a fresh Codex invocation while `wr-retrospective-*` commands were still absent from this session's `$PATH`. Continue with the released cache's absolute `bin/` path, or start a fresh session before relying on shim discovery. <!-- signal-score: 6 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
