## Rotated 2026-07-03 (Tier-3 budget)

- **Moving a changeset to `docs/changesets-holding/` does NOT keep the code from shipping — it only withholds version attribution + CHANGELOG entry.** npm publishes main's package directory contents; any sibling-changeset-driven release ships ALL committed code, held or not. Witnessed 2026-06-11 (P220 AFK iter): the P220 Step 0d fix's changeset was held 2026-06-08, yet `npm pack @windyroad/itil@0.49.3` contains every fix file (SKILL prose + lib + script + bin shim) because 0.48.0/0.49.x released sibling changesets after the fix commit landed on main. The ADR-042 hold is changelog/attribution governance, NOT a shipment control — an above-appetite change held "out of the release queue" still reaches adopters on the next sibling release. Ticket captured 2026-06-11 for the framework gap. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-06-11 -->

- **"Cohort graduated" claims can be PARTIAL — verify each changeset file's location, never trust the cohort label.** The 2026-06-11 0.49.4 release drained 4 of the 6 work-problems-cohort held changesets (P206/P211/P212/P228) but left `p220-step-0d-outbound-responses-preflight.md` + `p214-step-5-is-error-transient-halt.md` still in `docs/changesets-holding/` despite the same reinstate criterion (0.47.15 eval) covering all 6. Before asserting "attribution shipped" for ticket N, check `ls docs/changesets-holding/ .changeset/` for N's specific file. K→V transitions stay valid either way (code ships regardless, see entry above); only the changelog-attribution claim needs the per-file check. - **The changeset-discipline gate (Check 2b) is now CHANGE-scoped, not plugin-scoped (P387, itil patch pending release 2026-06-27).** A `packages/<plugin>/` source commit no longer rides an UNRELATED in-scope changeset's coattails. Check 2b denies only on positive unrelated-sibling evidence: the commit message cites a work-item ID (`P<NNN>`/`RFC-<NNN>`/`STORY-<NNN>`) AND every in-scope changeset covering that plugin cites work-item ID(s) AND none overlap. Allow-on-ambiguity otherwise — a ticket-less commit, a prose-only changeset (no ID in filename/body), or an ID overlap all PASS. Practical impact in multi-ticket sessions: when you commit a P-X fix while a sibling P-Y changeset for the same plugin is already in scope, you must author P-X's OWN changeset (Check 2a) OR ensure a covering changeset cites P-X — otherwise the gate denies. The ADR-014 batch-grain still works because same-slice multi-commits share the slice's ticket. The hook extracts the commit ID from the `git commit` command it already parses (filename + body on the changeset side); ADR refs are deliberately NOT matched (cross-cutting, not change-identity). `changeset-detect.sh` is NOT a synced hook — single copy in `packages/itil/hooks/lib/`.
