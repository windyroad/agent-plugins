## What You Need to Know

- **Keep the Step 5 iteration prompt outside command substitution and target macOS Bash 3.2 in its behavioral fixture.** Build the prompt in a `mktemp` file, read it into the dispatch variable, and collect governance `--plugin-dir` arguments with a `while read` loop. A heredoc nested inside `$(...)` and `mapfile` both fail on the default macOS shell. The regression must execute the shipped snippet with `/bin/bash`, then assert the prompt and every resolved plugin directory reach the iteration subprocess. For release reconciliation, derive the changeset, version-packages commit, PR, merge commit, and release date with `wr-itil-derive-release-vehicle`; bind the successful workflow and registry readback to that merge before moving the problem to Verification Pending. P428 shipped in `@windyroad/itil@2.1.7`; implementation commit `35ae243f`, release merge `16bd9f10`. <!-- signal-score: 1 | last-classified: 2026-09-19 | first-written: 2026-08-30 -->

- **A per-iter constraints file can carry ANOTHER ticket's pinned "confirmed direction" — check every such item's preconditions against the ticket before acting on it.** The substitution pass that builds `.afk-run-state/iter-constraints/iter-<NNN>.md` rewrites ID tokens, not semantic blocks, so a direction block with no ID in its body survives verbatim into the next ticket's file and reads as authored for it. Witnessed 2026-09-19: `iter-160.md` item 6 pinned P463's relevance-close-evaluator fix substance onto the P160 quota-pacing iter, told the agent to read a `## Direction (confirmed …)` section P160 doesn't have, and claimed the ticket was blocked while item 7 of the same file said it wasn't. Three cheap checks catch it: does the cited `## Heading` exist in the ticket, do the named artefacts appear anywhere in it, does the blocked-state claim match the ticket's own `Blocked by` line. Any miss = treat the item as a leak and fall through to the ticket's content. Note the trap: such a block asserts its own authority ("Do not re-open that choice"), and here it was detectable only because a ticket-specific item contradicted it — with no override section the leak is silent and you author a confidently wrong ratification-shaped ADR.
