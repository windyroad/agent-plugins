# AFK and Subprocess Iteration

Learnings about `/wr-itil:work-problems` AFK loops, `claude -p` subprocess dispatch, and iteration-worker protocols.

## What You Need to Know

- **Parallel Claude sessions can create P-ticket numbering collisions.** `manage-problem` / `create-adr` compute `max(local, origin)+1` automatically; `work-problems` fetches origin at loop start. Outside the skills, `git fetch origin` and check the highest P-number before opening tickets.
- **ADR-020 auto-release is skipped inside AFK loops** (ADR-018 Step 6.5, avoids double-release). A fix scoped to non-AFK governance paths is NOT exercised by `/wr-itil:work-problems` iterations — when evaluating Fix Released tickets for closure, check which code path actually fired.
- **An AFK iter that keeps re-selecting a ticket it can only SKIP should PARK it, not re-queue `outstanding_questions` every iter.** When a ticket's remaining work is a genuine user-answerable decision (direction / deviation) that no `**Blocked by**` dependency edge can express — the blocker is a decision, not a ticket, so it can't suppress WSJF — the loop re-picks it as top-actionable every session and skips it, burning iters. The fix is to move it to `docs/problems/parked/` (Status → Parked; excluded from WSJF ranking per ADR-022), add a `## Parked` section with the un-park trigger (the decision being made), and refresh the README (row moves from WSJF Rankings to the Parked table). Still surface the decision via that iter's `outstanding_questions` so it reaches the user. `docs/problems/` is gate-excluded (architect/jtbd/style/voice all skip it), so parking is a doc-only commit; only the pipeline commit-score gate applies. Precedents on 2026-07-04: P244 (blocked on non-ticket F1/ADR-063 reconciliation, re-selected 7×) and P161 (blocked on M1/M2/M3 meta-ADR direction, re-selected 3×). "next interactive turn" is a named re-entry point, not a self-firing cadence — parking is what actually removes the re-selection waste. <!-- signal-score: 2 | last-classified: 2026-07-04 | first-written: 2026-07-04 -->
- **Headless `claude -p` activates ONLY user-scoped `enabledPlugins` — project-scoped plugins stay dark unless passed via `--plugin-dir`.** Project-plugin activation is trust-gated and headless skips the trust prompt, so an AFK iter subprocess in a project that enables the windyroad plugins at PROJECT scope gets no architect/jtbd/risk/voice-tone agents or gate hooks — it commits ungated and can't run retro-on-exit (`Task(wr-architect:agent)` → "agent type not found"). `--setting-sources user,project` does NOT fix it (it doesn't lift the trust gate); only `--plugin-dir <plugin-root>` does (verified upstream 2026-06-21). work-problems Step 5 now derives the dirs portably via `wr-itil-resolve-governance-plugin-dirs` (cache-parent highest-semver walk, ADR-080 — NOT `$PATH` order, which is frozen-stale mid-session) and splices `--plugin-dir` pairs into the dispatch. ## What Will Surprise You

- **The AFK work-problems orchestrator exports `WR_SUPPRESS_OVERSIGHT_NUDGE=1` + `WR_SUPPRESS_PENDING_QUESTIONS=1`, and these LEAK into bats subprocesses spawned by an iter.** Any hook-test suite whose hook self-suppresses on one of those guards must `unset` it in `setup()` or its count/output-emitting tests fail spuriously inside AFK iters while staying green in CI (CI doesn't export the guards). P391 fixed the four nudge suites (jtbd/architect/itil-rfc oversight-nudge + risk-scorer scaffold-nudge); the reference pattern is `itil-pending-questions-surface.bats` (unsets in `setup()` + `teardown()`).
