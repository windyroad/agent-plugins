## What You Need to Know

- **Born-`confirmed` ADRs are hook-blocked in AFK subprocesses even when the substance was drain-ratified.** The P348 oversight-marker guard denies any Write carrying `human-oversight: confirmed` without a same-session substance-confirm marker (which needs an AskUserQuestion + `wr-architect-mark-oversight-confirmed`). Don't fight it, and don't cite the ADR-091 born-confirmed precedent (that shape needs an interactive event): write `human-oversight: unconfirmed` + an oversight-note quoting the drain ratification; the `/wr-architect:review-decisions` drain promotes it trivially. - **Story ratification (ADR-090/096) has no AFK carve-out — an iter whose fix-vehicle RFC carries `stories: []` can only capture story infrastructure and hold.** Even with the fix direction substance-ratified (ADR-074 satisfied), ADR-089 requires ≥1 story, ADR-095 requires map membership at capture, and ADR-090 rule 3 + ADR-096 make ratify → accept → wire `stories:` → implement interactive-only. The AFK shape: capture the story-map + story born `human-oversight: unconfirmed` (legal — unconfirmed artefacts may exist), do NOT edit the RFC's frontmatter `stories:` array (the derived `## Stories` body table via the reverse-trace helper is fine), queue ratify→accept→wire→implement to `outstanding_questions`, report partial-progress. Witnessed P376 Gap 2 iter 2026-07-15 (took 3 architect reviews to converge); P456 tracks the friction fix. **Second witness P430 iter 2026-07-26, and it generalises: the ticket had no fix vehicle at all, so this is not specific to a pre-existing `stories: []` RFC — ANY fix-implementation iter now walks map → RFC → story → ratify and stops at ratify.** That iter's fix was a 3-line env-var guard plus one SKILL export line (effort S, approach covered by four existing ADR precedents) and it still could not land; the budget went to 3 architect + 2 style-guide + 2 voice-tone + 1 accessibility review and three new artefacts. Do not plan an AFK iter around landing code — plan it around authoring the vehicle and queueing the ratification, and say so in the summary. ## What Will Surprise You

- **The AFK work-problems orchestrator exports `WR_SUPPRESS_OVERSIGHT_NUDGE=1` + `WR_SUPPRESS_PENDING_QUESTIONS=1`, and these LEAK into bats subprocesses spawned by an iter.** Any hook-test suite whose hook self-suppresses on one of those guards must `unset` it in `setup()` or its count/output-emitting tests fail spuriously inside AFK iters while staying green in CI (CI doesn't export the guards). P391 fixed the four nudge suites (jtbd/architect/itil-rfc oversight-nudge + risk-scorer scaffold-nudge); the reference pattern is `itil-pending-questions-surface.bats` (unsets in `setup()` + `teardown()`).
