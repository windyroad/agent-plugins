# Releases and CI

Cross-session learnings about push:watch, release:watch, changesets, npm publish, and the GitHub Actions pipeline.

## What You Need to Know

- **The `push:watch` script** in root `package.json` is the sanctioned way to push — it runs `git push` then watches the CI run. The git-push-gate hook blocks bare `git push`. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **Never run `changeset version` locally.** The release pipeline handles versioning. To release: push with `npm run push:watch`, the pipeline creates a release PR, merge it with `npm run release:watch`. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->
- **Post-publish npm verification must tolerate registry propagation, while pre-publish verification must reject immutable version collisions.** A C4 recovery attempted to publish an already-existing `0.2.0`, then the corrected `0.2.1` publish was falsely marked failed because `npm view ... dist-tags.latest` briefly returned `0.1.7`. The shared verifier now checks the version before publish and retries the post-publish `latest` read; commits `cbcda3d1` and `5c33a97d`, release run `33187926547`. <!-- signal-score: -3 | last-classified: 2026-08-30 | first-written: 2026-08-29 -->

Load the archive when investigating older release / CI behaviour.
- **No `@windyroad/*` package depends on another — ZERO internal deps** (`grep -rn "@windyroad/" packages/*/package.json` matches only `"name"` fields). So `updateInternalDependencies: "patch"` is **inert**, `fixed`/`linked` are `[]`, and `packages/shared/` has no `package.json` (12 published pkgs, not 13). A release "bumping every package" is NOT a dependency cascade — changesets bumps exactly the packages named in the drained `.changeset/*.md` (verified: version commit `32c1f0e8` bumped 6 = union of 6 changesets' named pkgs). The 2026-06-28 all-package bump was caused by 16 queued release-metadata entries draining together; each bump was 1:1 with a real change, not a dependency cascade. See P394 (Known Error). <!-- signal-score: -1 | last-classified: 2026-08-30 | first-written: 2026-06-28 -->
