## What You Need to Know

- **An architect review unlocks edits only through a supported, caller-bound completion path and one unambiguous canonical verdict.** The shared marker writer accepts exactly one `**Architecture Review: PASS**` or `## Architecture Review: PASS` line. ISSUES FOUND, repeated or conflicting canonical verdicts, malformed headings, quoted examples, and narrative approval create no review, hash, or plan markers. The generated Codex completion transport records the parent session, checkout, reviewer role, and target at spawn time, then forwards the completed reviewer output to the shared marker writer under that parent context; unmatched targets, non-architect targets, and stale target reuse fail closed. Close the same fresh reviewer once through the native completion path. Never replay a verdict, guess a session id, or create marker evidence manually. - **The verdict heading must be TITLE CASE, and an all-caps one is discarded in silence.** Both accepted shapes anchor on `Architecture Review` in title case, while `<VERDICT>` itself is matched in caps — the parser mixes conventions, and the agent generalises to all-caps for the whole heading. `**ARCHITECTURE REVIEW: PASS**` matches neither shape, so the parsed verdict is empty, no marker is written, and the next gated edit refuses with "No architect review marker found for this session" — which reads as though no review happened. Re-spawning cannot fix it: the next spawn makes the same choice. Six consecutive spawns burned this way on 2026-09-04, across four rounds of genuine findings; the seventh landed only after reading `_architect_verdicts` in the hook source and telling the agent the exact string. Put the required literal in the spawn prompt from the start. Third facet on P468.
