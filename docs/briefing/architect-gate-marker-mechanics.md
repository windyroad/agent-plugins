# Architect Gate Marker Mechanics

How the `wr-architect:agent` completion reaches the shared marker writer and which verdict shapes carry authority. The P099 Tier 3 budget rotation split this file out of [`agent-hook-gate-quirks.md`](./agent-hook-gate-quirks.md) on 2026-07-26.

Sibling files: [`agent-hook-gate-quirks.md`](./agent-hook-gate-quirks.md) (other gate quirks), [`hooks-and-gates.md`](./hooks-and-gates.md) (gate inventory), [`agent-interaction-patterns.md`](./agent-interaction-patterns.md) (broader interaction discipline).

## What You Need to Know

- **An architect review unlocks edits only through a supported, caller-bound completion path and one unambiguous canonical verdict.** The shared marker writer accepts exactly one `**Architecture Review: PASS**` or `## Architecture Review: PASS` line. ISSUES FOUND, repeated or conflicting canonical verdicts, malformed headings, quoted examples, and narrative approval create no review, hash, or plan markers. The generated Codex completion transport records the parent session, checkout, reviewer role, and target at spawn time, then forwards the completed reviewer output to the shared marker writer under that parent context; unmatched targets, non-architect targets, and stale target reuse fail closed. Close the same fresh reviewer once through the native completion path. Never replay a verdict, guess a session id, or create marker evidence manually. - **The verdict heading must be TITLE CASE, and an all-caps one is discarded in silence.** Both accepted shapes anchor on `Architecture Review` in title case, while `<VERDICT>` itself is matched in caps — the parser mixes conventions, and the agent generalises to all-caps for the whole heading. `**ARCHITECTURE REVIEW: PASS**` matches neither shape, so the parsed verdict is empty, no marker is written, and the next gated edit refuses with "No architect review marker found for this session" — which reads as though no review happened. Re-spawning cannot fix it: the next spawn makes the same choice. Six consecutive spawns burned this way on 2026-09-04, across four rounds of genuine findings; the seventh landed only after reading `_architect_verdicts` in the hook source and telling the agent the exact string. Put the required literal in the spawn prompt from the start. Note also that the deny message's own escape hatch — `touch /tmp/architect-reviewed-$SID && rm -f …hash` — was refused by the auto-mode classifier, so the documented recovery is not reachable from inside the session. Third facet on P468. <!-- signal-score: 2 | last-classified: 2026-09-04 | first-written: 2026-09-04 -->
- **A gate that only unlocks on PASS cannot be cleared for a file that does not exist yet — stage the draft outside the gated path and point the reviewer at it.** The architect and JTBD gates write a marker only on a clean PASS verdict; ISSUES FOUND writes nothing, so the edit stays blocked. That is fine while the reviewer can read what you propose, but a NEW file under a gated path (`docs/decisions/`, `docs/stories/`) is a deadlock: you cannot write it without a marker, and a pre-edit prose description of it is what the reviewers keep returning ISSUES FOUND on, because they are judging a summary rather than the artefact. Write the full draft into the session scratchpad, give the reviewer its absolute path, say plainly that it lands at the gated path verbatim once passed, then copy it across on PASS. Both reviewers read files outside the repo without complaint, and their findings get sharply more specific once they are reading real text — on 2026-09-19 the JTBD reviewer's pre-edit pass raised five findings against a described ADR and its post-draft pass discharged all five by citing line numbers. Budget for two rounds per gated new file: one on the description to shape it, one on the draft to clear it.
