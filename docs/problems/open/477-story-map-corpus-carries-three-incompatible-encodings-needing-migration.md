# Problem 477: Nine story maps carry the superseded stacked encoding, and two more use bespoke encodings, all needing migration to the rendered grid

**Status**: Open
**Reported**: 2026-08-05
**Priority**: 6 (Low) — Impact: 2 × Likelihood: 3
**Origin**: found while fixing the shipped template (ADR-102)
**Effort**: M. WSJF = (6 × 1.0) / 2 = 3.0.
**WSJF**: 3.0
**JTBD**: JTBD-008
**Persona**: developer

## Description

ADR-102 replaced the story-map encoding: a map is now a rendered grid — backbone activities as columns, release slices as rows, task cards in cells — generated by `wr-itil-render-story-map` from a `<script id="story-map-data">` island inside the map itself.

Eleven maps predate it, in three different shapes:

- **Nine are the superseded stack** (STORY-MAP-001, 004-011): `<section class="backbone">` blocks with one `<h2 data-rib>` heading each. No columns, no release dimension, no cells. Not story maps in Patton's sense — lists wearing map vocabulary.
- **STORY-MAP-002 is a genuine two-dimensional map** — five activities by three release bands, CSS-grid encoded rather than table-encoded. It needs re-encoding onto the canonical template, not re-conceiving; its content already has the right shape.
- **STORY-MAP-003 is partial** — five activities, no release dimension. Needs a release axis, then re-encoding.

Only STORY-MAP-012 is on the canonical encoding. That the corpus held three incompatible shapes, with nothing marking which was canonical, is the underlying problem the renderer settles.

## Symptoms

- Opening any of the nine stacked maps shows a list, so the thing a map exists to show — what ships together, read across a row — is not visible.
- The style guide, voice guide and `docs/story-maps/README.md` now describe the grid as normative, so all eleven are non-conformant against its own documented schema.
- A maintainer opening one to learn the house shape learns the wrong one. That copy-the-sibling loop is exactly how all thirteen drifted together in the first place; the renderer removes the loop for new maps but the eleven remain as misleading exemplars.

## Impact Assessment

- **Who is affected**: anyone reading an existing map, and any agent that ignores the skill's prohibition and reaches for a sibling anyway.
- **Frequency**: every time an old map is opened.
- **Severity**: Low. Nothing is broken mechanically — see Dependencies — the cost is comprehension and a wrong exemplar.

## Root Cause Analysis

Both the shipped template and the whole corpus were wrong together, so cloning the corpus propagated the defect instead of exposing it. ADR-102 fixed the generator; the artefacts it already produced were deliberately left for a separate pass rather than bundled into that change.

### Investigation Tasks

- [ ] For the nine stacked maps, derive a real journey backbone. This is the substantive part and cannot be mechanical: the existing headings are mostly invariants ("Leave no unscored way out"), not steps a persona walks through, so the backbone has to be re-authored rather than transposed.
- [ ] For STORY-MAP-002, transpose rather than re-author — its activities and release bands already exist and only need re-encoding onto the template.
- [ ] For STORY-MAP-003, add a release axis, then re-encode.
- [ ] Decide release bands per map. Most existing maps have no release dimension at all, so this is new information, not a reshuffle.
- [ ] Write each map's data island and render with `wr-itil-render-story-map`.
- [ ] Re-ratify each migrated map. The shape change drifts the stored fingerprint, so a human confirm is required per ADR-090 — four currently carry an `oversight-hash`.
- [ ] Confirm reverse-trace still resolves after migration (`update-story-references-section.sh <map> "Story Maps"`).

## Dependencies

- **Depends on**: ADR-102 (shipped encoding + renderer), which must be ratified first.
- **Safe to defer**: every consumer matches either `data-story-id` or the `<meta>` block, and neither is container-dependent — `reconcile-story-maps.sh` and `render-story-map-index.sh` read only `<meta>` and the filename. A mixed corpus is therefore mechanically safe, which is why this is Low rather than blocking.
- **Composes with**: the ADR-102 hash amendment. Migration is the deliberate one-time re-hash that amendment calls for.
