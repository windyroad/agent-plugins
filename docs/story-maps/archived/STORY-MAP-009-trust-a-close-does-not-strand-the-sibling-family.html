STORY-MAP-009: Trust that a close does not strand the sibling family

Closing a problem ticket should mean the work it is traceable to is genuinely settled, not just that one file moved to a closed folder. Tickets in this backlog already record which siblings they compose with — maintainers have authored 212 such edges across the open, known-error and verifying corpus — but nothing reads them. Every close path checks only the ticket in hand, so a ticket can close while a sibling it is recorded as composing with stays open and nobody makes that call. Twenty-nine already-closed tickets name a sibling that is still open or known-error today; no close path surfaced the edge in any of them. This map covers making the close paths family-aware: scan the composes-with edges, surface the ones still outstanding, and queue the disposition for the maintainer instead of blocking the close.
