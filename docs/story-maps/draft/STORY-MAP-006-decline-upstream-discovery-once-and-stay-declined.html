STORY-MAP-006: Decline upstream discovery once and stay declined

A project that never wants its upstream tracker polled for inbound problem reports can say so once, and the framework records that answer as an empty channel list. Saying no should then cost nothing. Today it costs a full pre-flight subprocess on every autonomous loop: the staleness check that decides whether to refresh the inbound-discovery cache looks only for the presence of the config file, so a recorded "no thanks" reads as "never checked", and the loop keeps dispatching a pass that has nothing to poll and so never writes the cache that would quiet it. This map covers teaching that check to read the answer it was given. (Traces: P431, inbound #341; JTBD-006.)
