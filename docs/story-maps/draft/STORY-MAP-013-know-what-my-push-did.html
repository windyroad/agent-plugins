What this map traces to

Persona: developer — the person doing the work, with tech-lead secondary. The binding constraint is that repo shape varies: this developer's projects do not share one release stack, so tooling that names a command must discover it rather than assume it.

Jobs mapped: JTBD-012 (know what my push did without leaving the terminal) is the spine — every activity here is one of its desired outcomes. JTBD-003 (compose only the guardrails I need) is what makes the R1 band obligatory rather than a nicety: a plugin installed for its reporting must not block a project that has no pipeline to report on.

Problems this closes: P435 — the push gate is hardcoded to this repository's shape and over-fires in projects without the pipeline it assumes. The R1 band is that fix.

Decisions the journey rests on: None yet. The behaviour mapped here is implemented today inside the risk-scorer's push gate, fused with the risk concern mapped at STORY-MAP-012.

Open questions: This map asserts no plugin boundary. Whether these concerns ship as one plugin or two is undecided as of 2026-08-05. Two activities here block rather than report, so 'one blocks, the other reports' is not the dividing line. Pushing to a pipeline-owned branch has a genuine claim on both maps and is drawn on STORY-MAP-012 today; that duplication is recorded rather than resolved.
