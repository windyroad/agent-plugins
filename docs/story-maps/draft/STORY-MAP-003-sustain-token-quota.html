STORY-MAP-003: Sustain My Token Quota Across the Week and Across Surfaces

User-story map for JTBD-010 (Sustain My Token Quota Across the Week and Across Surfaces), grounding the reopened P160 and its lineage-repair ticket P443. Backbone (the developer's journey across a week on one shared account quota) × ribs (releases) × slices (stories), per Patton, User Story Mapping (O'Reilly, 2014). Born human-oversight: unconfirmed per ADR-090 — awaiting ratification via /wr-itil:manage-story-map.

This map exists to make the extraction argument concrete: quota-pacing shares no backbone activity with the two existing story maps (STORY-MAP-001 and STORY-MAP-002, both JTBD-008 "decompose a fix into coordinated changes"). It is an independent journey, which is why the capability belongs in its own plugin (@windyroad/quota-pacing, ratified 2026-07-08) rather than synced across the seven governance plugins. Release 1 (the throttle) shipped 2026-07-06; Release 2 (own plugin + self-installing producer) is the fix that closes the P160/P443 adopter-inert and mis-placement gaps.

Backbone — the developer's journey across a week on one shared quota

1. Quota state reaches my tooling
2. Every tool call self-paces
3. Ease back when ahead, don't stop
4. Keep weekly headroom for chat/Cowork
5. Works without hidden setup
