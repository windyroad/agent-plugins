STORY-MAP-007: A correction to the agent's conduct holds in every project

A maintainer should only have to correct the agent's conduct once. Today that correction dies with the session it lands in, and it never reaches another project at all: the agent's defaults reset, so a correction held only in conversation, or in a maintainer's private notes, changes nothing for the next turn and nothing for anyone who installs the plugins. This map covers carrying those corrections as rules that ship. Its first rib carries the correction an inbound report already raised: the agent asks for a long URL through a fixed-options picker with no field to paste into. Its second carries another: the agent sends a file to an outside reviewer with commits still unpushed, so the reviewer re-flags problems the agent already fixed. Slices below link to Markdown story files. (Traces: P438, inbound #324; P439, inbound #326; JTBD-011, JTBD-101.)

Answerable prompts

Ask for a URL in a shape I can paste into

Current handovers

Have my reviewer read the version I actually have

Two ribs so far. The agent also hands out off-ramps nobody asked for and narrates its own conduct instead of doing the work — captured as P445 — which is the same job seen from a third angle and belongs here as a third rib, "No off-ramps I never asked for", once it has a story to hang on it. Building that rib empty today would be scaffolding for work not yet scoped, so it is named here instead.
