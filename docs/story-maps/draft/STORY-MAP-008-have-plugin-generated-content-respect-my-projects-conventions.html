STORY-MAP-008: Have plugin-generated content respect my project's conventions

A plugin is a guest in the repository that installs it. When one of these plugins writes content into that repository — an ADR skeleton, a regenerated decisions compendium, a rendered verification-queue cell, an audit-log entry — the adopter is left holding whatever characters the generating template happened to use. Five inbound reports have now hit the same wall. In each, the adopter's own project hard-blocks the em-dash, the adopter's own Edit and Write hooks fire correctly on it, and the text tripping those hooks arrives from a cached plugin they cannot edit. Scrubbing it by hand is a treadmill, because the next regeneration puts it back. This map covers making generated output portable by default, so a stricter project than ours can install the suite without inheriting a block it has no way to clear. Its first rib carries the four emitting surfaces the reports actually raised. The slice below links to a Markdown story file. (Traces: P424, inbound #185, #186, #219, #223, #319; JTBD-303, JTBD-101.)
